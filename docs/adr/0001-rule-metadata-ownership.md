# Separate rule evidence from rule explanations

The conformance package remains the source of truth for official rule identity and fixture coverage because it already verifies that evidence against the pinned ruleset. The rules package consumes those records at build time, publishes a validated self-contained snapshot, and owns project-authored explanations, corrective guidance, examples, and documentation presentation. It has no runtime dependency on the private conformance package. The linter constructs versioned remediation URLs without depending on the rules package; rules-site contract tests verify that representative diagnostic links resolve. This avoids competing inventories and a lint/rules package cycle while keeping evidence separate from editorial guidance, at the cost of build-time integration and a URL contract shared across packages.
